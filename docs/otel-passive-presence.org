* Core Thesis
  :PROPERTIES:
  :LAYER:  L1.5 (presence) — passive tap path
  :STATUS: [C] Conjecture C-015, untested against multi-worktree scenario
  :END:

  Claude Code agents emit OTEL telemetry as a side effect of normal
  operation. Every tool call, file path touched, session ID, and
  ~prompt.id~ is broadcast to a collector before any ~aq~-aware code
  runs. This is not observability bolted on — it is gossip that already
  exists, waiting to be tapped.

  The implication: rather than requiring agents to write to ~AQ_HOME~
  or publish to an MQTT topic, a bridge process can read OTEL log events
  off the collector and re-emit them as ~aq~-compatible NDJSON presence
  records. The agent cooperates with nothing. The bootstrap paradox
  (F-1) dissolves — the OTEL emission precedes ~aq~ initialization.

** Enabling Telemetry

#+begin_src sh
#!/bin/sh
# Minimal config for aq presence tap
export CLAUDE_CODE_ENABLE_TELEMETRY=1
export OTEL_METRICS_EXPORTER=otlp
export OTEL_LOGS_EXPORTER=otlp
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317

# Tighten log export interval for <2s lag (default 5s)
export OTEL_LOGS_EXPORT_INTERVAL=2000

# Optional: enable tool details for worktree claim inference
# WARNING: may include file paths with sensitive names
export OTEL_LOG_TOOL_DETAILS=1

# Tag sessions with agent identity for aq routing
export OTEL_RESOURCE_ATTRIBUTES="agent.id=unknown,worktree=unknown"
#+end_src

** Emitted Events (as aq presence signals)

  Claude Code emits structured log events via the OTEL logs protocol —
  *not* as OTel metrics. Events arrive in ~otel_logs~, not ~otel_metrics~.

  | Event name                   | aq-relevant attributes                        | Presence signal derived       |
  |------------------------------+-----------------------------------------------+-------------------------------|
  | ~claude_code.user_prompt~    | ~session.id~, ~prompt.id~, prompt length      | session alive, agent identity |
  | ~claude_code.api_request~    | ~model~, token counts, cost, duration         | active processing             |
  | ~claude_code.tool_result~    | tool name, ~tool_input~ (paths), success      | *implicit worktree claim*     |
  | ~claude_code.tool_decision~  | ~decision_type~ accept/reject                 | permission boundary events    |
  | ~claude_code.api_error~      | error type, model                             | agent degraded signal         |

  Key insight: ~claude_code.tool_result~ with ~OTEL_LOG_TOOL_DETAILS=1~
  includes ~tool_input~ with file paths. A ~Write~/~Edit~ tool event is
  a soft claim; a ~commit.count~ event with a ~git_commit_id~ is a
  *durable, named claim*.

* The Bootstrap Paradox Resolution
  :PROPERTIES:
  :FAILURE-REF: F-1 (DOGFOODING.md)
  :CONJECTURE: C-015
  :END:

  F-1 states: ~aq~ needs ~aq~ to announce ~aq~. No agent can broadcast
  its own presence before the presence layer is initialized.

  The OTEL tap sidesteps this entirely:

  The agent need not know ~aq~ exists. The collector is shared
  infrastructure. The bridge is a single always-on process.

  [C-015] *Claude Code OTEL spans, tapped via collector bridge,
  constitute a passive L1.5 presence signal requiring zero agent-side
  aq instrumentation, resolving F-1 bootstrap paradox.*

* Mapping OTEL Signals to aq Semantics

  | OTEL signal                              | aq concept          | TTL logic                        |
  |------------------------------------------+---------------------+----------------------------------|
  | ~session.id~ first seen                  | agent announce      | start TTL on first event         |
  | ~user_prompt~ events continuing          | presence heartbeat  | reset TTL on each event          |
  | ~tool_result~ Write/Edit + path          | soft worktree claim | claim until session end          |
  | ~commit.count~ + ~git_commit_id~         | *durable claim*     | named, SHA-addressable           |
  | ~pull_request.count~                     | branch complete     | implicit withdraw from branch    |
  | ~tool_result~ Read + path                | soft interest       | no claim; gossip only            |
  | ~api_error~ event                        | agent degraded      | presence continues; state=error  |
  | session idle (no events > N sec)         | implicit withdraw   | TTL expiry; LWT analog           |

* Privacy and Sensitivity

  - By default: file contents never included; prompt text not logged;
    only prompt *length* is recorded.
  - ~OTEL_LOG_USER_PROMPTS=1~: includes full prompt text. Do not enable
    on shared collector without access control. Not needed for aq presence.
  - ~OTEL_LOG_TOOL_DETAILS=1~: includes file paths and bash command strings.
    Required for worktree claim inference. May expose sensitive paths.
    Enable only on personal/homelab collector.
  - ~OTEL_RESOURCE_ATTRIBUTES~ formatting: comma-separated ~key=value~,
    *no spaces allowed* in values. Use underscores or percent-encode.
  - OTEL Web (claude.ai/code): not yet supported in sandbox environment.
    CLI and VS Code extension only.
